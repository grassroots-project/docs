# 池塘模式

Grassroots Project 的组织方式是一个开放的池塘。

## 什么是池塘模式？

传统组织是层级结构：老板 → 经理 → 员工。

池塘模式不同：

- 没有固定层级
- 资源开放共享
- 自由组合协作
- 价值在博弈中发现

## 三个池塘

### 📋 任务池

存放**开放任务**。

| 属性 | 说明 |
|------|------|
| 内容 | 待完成的任务 |
| 谁可以添加 | 任何成员 |
| 谁可以领取 | 任何成员 |
| 存放位置 | [GitHub Issues](https://github.com/grassroots-project/tasks/issues) |
| 前端 | [任务池页面](https://grassroots-project.github.io/website/pages/tasks.html) |

**任务属性**：
- 优先级：P0（必须先做）、P1（重要）、P2（探索）
- 状态：待领、进行中、已完成
- 技能标签：文案、设计、技术、运营等

### 👥 人才库

存放**成员信息**。

| 属性 | 说明 |
|------|------|
| 内容 | 成员技能、时间、贡献 |
| 谁可以编辑 | 成员自己 |
| 存放位置 | [GitHub Issue #1](https://github.com/grassroots-project/tasks/issues/1) |
| 前端 | [人才库页面](https://grassroots-project.github.io/website/pages/people.html) |

**成员属性**：
- 加入时间
- 技能标签
- 时间承诺
- 当前任务
- 历史贡献

### 📦 资源池

存放**共享资源**。

| 属性 | 说明 |
|------|------|
| 内容 | 比特币、知识、工具、人力 |
| 谁可以添加 | 任何成员 |
| 存放位置 | [GitHub Issue #2](https://github.com/grassroots-project/tasks/issues/2) |
| 前端 | [资源池页面](https://grassroots-project.github.io/website/pages/resources.html) |

**资源属性**：
- 类型：比特币/知识/工具/人力
- 状态：可用/已占用/待规划
- 负责人
- 使用说明

## 核心原则

### 1. 不批准，只记录

传统组织：申请 → 审批 → 执行。

池塘模式：行动 → 记录 → 复盘。

- 不需要申请批准
- 只需要记录你做了什么
- 用结果说话

### 2. 自由组合

- 任何人可以领取任何任务
- 任何人可以使用任何资源（先沟通）
- 协作自然形成，不需要安排

### 3. AI 引导

- AI 助手帮助理解规则
- AI 推荐适合的任务
- 降低认知门槛

### 4. 价值在博弈中发现

- 贡献被记录
- 贡献被评估
- 价值通过市场机制发现

## 工作流程示例

### 新人加入

```
1. 阅读项目介绍
2. 完成筛选问卷
3. 收到回复
4. 添加信息到人才库
5. 领取第一个任务
```

### 完成任务

```
1. 从任务池领取任务
2. 开始工作
3. 需要资源？从资源池申请
4. 完成任务
5. 更新任务状态
6. 更新人才库（历史贡献）
```

### 使用资源

```
1. 查看资源池
2. 找到需要的资源
3. 与负责人沟通
4. 使用资源
5. 更新资源状态
```

## 与传统组织的对比

| 维度 | 传统组织 | 池塘模式 |
|------|---------|---------|
| 结构 | 层级制 | 扁平化 |
| 任务分配 | 上级指派 | 自由领取 |
| 资源使用 | 需要审批 | 沟通后使用 |
| 评价机制 | 上级评价 | 贡献记录 |
| 加入门槛 | 面试筛选 | 筛选问卷 |
| 退出机制 | 离职手续 | 自由退出 |
